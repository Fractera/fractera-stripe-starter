# Step 2 — the payment doors: Checkout, status, journal, signed webhook

**What.** Node step 573-3 built the payment part of this element: `POST /api/stripe-checkout` (a Stripe Checkout payment link for an
element of the node), `GET /api/stripe-status?id=` (paid · open · expired), `GET /api/stripe-payments?element=` (the payments recorded for an
element) — node doors with the node key, made by `npm run door:add` — and `POST /api/stripe-webhook` (public, the Stripe signature decides;
named in `proxy.ts` PUBLIC_API_PREFIXES and in the card's `private`). The Stripe SDK `stripe@23.0.0` (exact). The keys come from the node
screen Settings → Payments → Web2 into `.env.local`; without them the doors answer `503 no_stripe_keys`.

**How.** `lib/stripe/stripe.mjs` (client or null; a signature-only client), `lib/stripe/journal.mjs` (`<SERVICE_DATA_DIR>/stripe/payments.jsonl`,
one line per event id, no buyer data). The element and the order reference ride in the session metadata and the payment metadata, so the
webhook and a refund name them. Webhook retries: up to three days in live mode, three times over a few hours in a sandbox
(docs.stripe.com/webhooks, read 2026-10-23).
